# ИС структурированных данных из текстовых отчетов

Тема: Разработка информационной системы формирования, верификации и управления структурированными данными на основе текстовых отчетов.

Исходные модели находятся в src, прототипы Strategy - в prototype, сборщик - в ci. Общие определения и стиль используются локальными представлениями пяти участников. C4-PlantUML 2.12.0 включен с лицензией. Приемочный рендер закреплен на PlantUML 1.2025.2 с проверкой SHA-256.

## Этапы работы

ЛР1-ЛР4 выполняются с локальной проверкой моделей. CI подключается
тимлидом в начале ЛР5 через служебный PR chore/ci-lr5. Контрольные JSON
участников добавляются только в ЛР5. Далее принимаются пять итоговых PR.
Команды ниже относятся к проекту после подключения автоматической сборки.

## Проверка

Нужны Python 3.11 или новее, Java 21 и Graphviz. В GitHub Actions используется ubuntu-24.04. Установить зависимости и запустить:

```sh
python -m pip install -r ci/requirements.txt
python ci/build.py --mode auto
```

В рабочих ветках до общей интеграции команда выполняет частичную проверку доступных моделей. Все имеющиеся include и связи проверяются строго. Контрольная точка участника перечисляет файлы, обязательные для его этапа. В итоговом PR тимлида признак ci/integration-complete.json включает полную сборку: 46 исходников архитектуры и одну схему сборки в docs/flows, 48 представлений и 54 теста прототипов. После завершения интеграции удаление модели является ошибкой. Режим и список еще не включенных моделей видны в .build/summary.json.

Для принудительной полной проверки: `python ci/build.py`. Для проверки структуры без рендера: `python ci/build.py --mode auto --lint-only`. Можно указать ранее скачанный закрепленный JAR через `--jar /path/plantuml.jar`. JAVA и GRAPHVIZ_DOT задают пути к инструментам.

Успешный рендер сохраняет PNG/SVG в .build/artifacts. Журналы находятся в .build/logs. Изображения публикуются только после успешных проверок. При отказе прежний артефакт удаляется.

## Ветки и прием изменений

Пять веток: feature/teamlead, feature/backend, feature/analyst, feature/techdoc, feature/devops. ЛР1-ЛР4 выполняются в своих ветках. В ЛР5 открываются пять PR в main. Четыре PR разработчиков рассматривает тимлид. Последним открывается PR тимлида с общей интеграцией; его рассматривает другой участник. Порядок описан в docs/github-setup.md. Для сохранения отдельных коммитов использовать merge без squash.

Полная проверка документации не является развертыванием самой ИС. Тесты работают с адаптерами прототипов и не обращаются к реальным внешним сервисам.

## Первоначальные материалы

Корневой main.puml, diagrams/ и backend/ сохраняют первоначальные модели.
Актуальные входы CI находятся в ci/catalog.json. Границы проверки
описаны в docs/existing-repository.md.
