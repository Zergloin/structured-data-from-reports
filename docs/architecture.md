# Правила общей модели

Тема: Разработка информационной системы формирования, верификации и управления структурированными данными на основе текстовых отчетов.

Восемь контейнеров: web_app, api, worker, integration, database, files, extraction_queue, integration_queue. Обе очереди обслуживает один RabbitMQ. Семь компонентов worker сохранены из ЛР2. integration получает задания и фиксирует исход через SystemApi, без прямого подключения к database. API публикует первоначальные и повторные задания через outbox. Сервис извлечения сохраняет технический результат; запись принимает эксперт. Опубликованные схемы и принятые снимки неизменяемы. Экспорт связан с фиксированным export_id.

ЛР1: контекст и контейнеры. ЛР2: компоненты. ЛР3: UML и проверяемые прототипы Strategy. ЛР4: ландшафт, динамика и развертывание. ЛР5: совместная сборка. Идентификаторы не переименовываются в индивидуальных моделях. Стили задаются только в src/style.puml. В C4 используются Rel с действием и протоколом. Макросы направленных связей и ручной раскладки запрещены. UML-связи классов сохраняют свою нотацию.
