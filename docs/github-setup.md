# Порядок командной работы и интеграции

Общая основа до ЛР1 содержит определения, стиль и библиотеку C4-PlantUML.
Папки ci и workflow на этапе подготовки нет. ЛР1-ЛР4 выполняются
в feature/teamlead, feature/backend, feature/analyst, feature/techdoc
и feature/devops. Каждый участник проверяет свои модели локально
и фиксирует изменения в своей ветке. Ранних запусков Actions нет.

В начале ЛР5 тимлид создает от main временную ветку chore/ci-lr5.
Отдельный служебный PR добавляет ci/build.py, каталог, глоссарий,
закрепленные зависимости и .github/workflows/render-docs.yml.
Первый запуск проверяет общую основу в partial. После review и merge
architecture-build настраивается как обязательный статус для main.

Затем backend, analyst, techdoc и devops объединяют main со своей веткой,
добавляют контракт и ci/contributions/<роль>.json с lab: 5 и открывают
итоговые PR в main. Контрольные JSON впервые появляются именно в ЛР5.
Порядок merge: backend, analyst, techdoc, devops. Тимлид проводит review.
Перед каждым PR и после изменения main выполняются fetch, merge origin/main
и push. После исправлений проверяется актуальный SHA, review обновляется.

После четырех merge тимлид объединяет main со своей веткой и добавляет
общие сборочные модели, контракт и ci/integration-complete.json.
Пятый итоговый PR рассматривает другой участник. Для него обязателен full:
47 входных файлов, 48 представлений, 48 PNG, 48 SVG и 54 теста.
После merge проверяется еще один полный запуск на main.

Все слияния сохраняют отдельные коммиты: Create a merge commit, без squash.
До ЛР5 защита main может требовать PR и review. Обязательный статус CI
добавляется после первого фактического запуска в ЛР5.
Workflow запускается при push в main и feature/** и при PR в main.
До итогового признака работает partial: отсутствующие чужие модели
не мешают проверке своей части. При этом все имеющиеся include проверяются.
Полные функциональные тесты запускаются после итоговой интеграции.
Удаление принятого признака или контрольной точки не ослабляет проверку.

Каждый использует собственные user.name/user.email. Ссылки на PR, review
и Actions фиксируются по реальным действиям в репозитории.

Работа ведется в https://github.com/Zergloin/structured-data-from-reports.
Исходные материалы и коммит PR #1 сохраняются в истории.
